# Repository Guide

This guide explains what every folder and file in the project is for, how they connect, and the order to run them in. Read it together with the [project report](project_report.md).

## 1. The project in one paragraph

A household in Ilocos Norte pays INEC a monthly bill of ₱12.36/kWh, based on the September 2026 bill. The project asks **how many kWp of rooftop solar (no battery) the household should install to cut that bill the most, and how sure we can be.** Weather changes from day to day, so the project does not use a single "average year". It simulates thousands of possible years:

```
weather (Markov chain) → solar output → household load → INEC bill → compare PV sizes
```

Each arrow is one Python module in `src/`. Section 3 lists them.

## 2. Folder structure

```
ilocos-norte-solar-bill-optimization/
├── README.md              quick start: what the project is and the commands to run
├── requirements.txt       Python packages needed (numpy, scipy, matplotlib, SALib)
├── .gitignore             files git should ignore (virtual env, caches, editor config)
├── data/                  all INPUTS
│   ├── raw/               data downloaded from outside sources, never edited by hand
│   ├── processed/         data computed from raw/ by the code
│   ├── bills/             the household's real electricity bills
│   └── appliances.csv     list of household appliances
├── src/                   all CODE (the model)
├── results/               all OUTPUTS (figures, tables, logs)
└── docs/                  all WRITING (report, plan, concept, this guide)
```

**Rule of thumb:** inputs live in `data/`, code in `src/`, outputs in `results/`, and explanations in `docs/`. Files in `results/` and `data/processed/` can always be regenerated by running the code again.

## 3. `data/`: the inputs

| File | What it is | Used for |
|---|---|---|
| `raw/nasa_power_daily_batac.csv` | Daily weather for **Batac City** from NASA POWER satellite data, 2001–2024 (8,766 days). Columns: date, clearness index (`ALLSKY_KT`), ground and top-of-atmosphere sunlight, mean/max/min temperature. (Laoag shares the same ~50 km NASA grid cell, so its data were identical and are not kept.) | Teaching the model how sunny and how hot each day of the year tends to be. |
| `raw/tariff/URS-January-2020.pdf` | INEC's official unbundled rate schedule (Jan 2020). | The list of bill line items (generation, transmission, VAT, universal charges, ...). |
| `raw/tariff/inec_residential_rate.html` | Saved news page with the April 2026 INEC rate. | Updating the 2020 rates to 2026. |
| `processed/tpm_batac.npz` | Transition probability matrices (TPMs) fitted from the Batac weather. Created by `src/estimate_tpm.py`. | The Markov chain that generates synthetic weather. |
| `bills/bills.csv` | **The real household bill:** September 2026, 464 kWh, ₱5,739.45, aircon = yes, no solar yet. | Calibrating the model to this household, and back-testing. |
| `bills/bills_template.csv` | Empty copy showing the column format. | Adding more bills or more households. |
| `appliances.csv` | Household appliances with wattage, how often they are used and at what hours (fridge, fans, aircon, rice cooker, washing machine, ...). | Building the **hourly shape** of electricity use. |

**`bills.csv` columns:** `household_id`, `year`, `month`, `kwh` (energy billed), `pesos` (total due), `aircon` (1/0), `pv_kwp` (solar size, 0 = none), `import_kwh` and `export_kwh` (only for homes already on net metering).

## 4. `src/`: the model code

Run every module from the project root as `.venv/bin/python -m src.<name>`.

### 4.1 The five model layers

| Layer | File | What it does, in plain words |
|---|---|---|
| 1. Weather | `markov.py` | Generates random but realistic sequences of sunny, partly cloudy and cloudy days. A **Markov chain** means tomorrow's weather depends on today's, so cloudy spells last several days, as they do in the rainy season. Separate probabilities are used for the dry and wet seasons. Daily values are then split into hours. |
| 1b. Solar output | `pv.py` | Converts sunlight into kWh produced by the panels for a given size (kWp), including heat losses. |
| 1c. Temperature | `temperature.py` | Generates daily and hourly temperature linked to the weather (cloudy days are cooler). Drives fan and aircon use. |
| 2. Household load | `load.py` | Builds hourly electricity use from `appliances.csv`: who is home, when people cook, and how much aircon runs on hot days. |
| 3. Bill | `tariff.py` | Computes the INEC bill line by line (generation, transmission, system loss, distribution, VAT, universal charges, ...) and applies **net metering**: credit for solar energy sent to the grid. |
| 4. Simulation | `simulation.py` | The **Monte Carlo engine**: runs the layers above for thousands of random years. Every PV size sees the *same* random weather (common random numbers), so differences between sizes come from the panels, not from luck. |
| 5. Optimization | `optimization.py` | Tries PV sizes from 0 to 6 kWp in 0.5 steps and picks the best one by expected cost, by bad-year risk (CVaR) or by the chance of exceeding a budget. Also tests shifting appliances (e.g. washing) into sunny hours. |

### 4.2 Data preparation

| File | What it does |
|---|---|
| `fetch_nasa_power.py` | Downloads the NASA POWER weather files into `data/raw/`. Needs the internet; run once. |
| `estimate_tpm.py` | Counts how often each weather state follows each other state in the 24-year record and saves the probabilities to `data/processed/tpm_batac.npz`. |

### 4.3 Checks (does the model behave like reality?)

| File | What it checks | Output |
|---|---|---|
| `validate_generator.py` | Does the synthetic weather look like real Batac weather (monthly averages, cloudy-spell lengths, day-to-day correlation)? | `results/generator_validation.*` |
| `validate_load.py` | Are simulated temperature and household load realistic (seasonality, which appliances use the most)? | `results/load_validation.*` |
| `convergence.py` | How many simulated years are enough for stable answers? | `results/convergence.*` |
| `backtest.py` | Does the model's bill match the real bills in `bills.csv`? The September 2026 bill was off by 5.1% before calibration. | printed to the screen |

### 4.4 Analysis tools

| File | What it does |
|---|---|
| `household.py` | **The main tool for this household.** Takes the real bill(s), calibrates the model to them, and prints a table of PV sizes with yearly bill, savings and payback, plus a recommendation. Works with one bill (`--month 9`). |
| `persistence.py` | **Cloud-persistence test on your household:** compares Markov-chain weather with independent random days, both calibrated to your bill. Writes `results/persistence.txt`. |
| `sensitivity.py` | **Sobol sensitivity analysis:** which uncertain input (panel price, rate increases, panel ageing, discount rate, ...) changes the answer most. |
| `__init__.py` | Empty file that makes `src/` a Python package. |

## 5. `results/`: the outputs

| File | From | Shows |
|---|---|---|
| `generator_validation.png/.txt` | `validate_generator.py` | Synthetic vs real weather. |
| `load_validation.png/.txt` | `validate_load.py` | Temperature and load checks. |
| `convergence.png/.txt` | `convergence.py` | Answers stabilising as the number of simulated years grows. |
| `optimization.png/.csv`, `optimization_run.log` | `optimization.py` | Bill, risk and payback for each PV size. Uses the September 2026 bill (5,677 kWh/yr, aircon, generation-only credit). |
| `persistence.txt` | `persistence.py` | Effect of ignoring cloud persistence on your household's bills (report §4.5). |
| `sensitivity.png/.txt`, `sensitivity_run.log`, `sensitivity_samples.npz` | `sensitivity.py` | Which inputs matter most. The `.npz` holds the raw samples. |

**`.png`** files are figures for the report, **`.txt`/`.log`** files are the printed numbers, **`.csv`** files are tables you can open in Excel, and **`.npz`** files are compressed numpy data.

## 7. Running order

```
1. fetch_nasa_power     download weather          (once; needs internet)
2. estimate_tpm         fit Markov chain          → data/processed/
3. validate_generator   check weather             → results/
4. temperature          fit temperature model
5. validate_load        check load                → results/
6. convergence          choose number of runs     → results/
7. simulation           size sweep
8. optimization         best PV size              → results/
9. household            YOUR bill → recommendation
10. sensitivity         what matters most         → results/
11. backtest            model vs real bills
```

For the household result alone, steps 1–2 are already done, so run:

```
.venv/bin/python -m src.household --kwh 464 --pesos 5739.45 --month 9 --aircon --offset generation
```

**Current answer:** about **4.5 kWp**, saving about ₱51,000/yr with a ~4-year payback, or 3.5–4.0 kWp if the hot September inflated the bill.

## 8. Glossary

| Term | Meaning |
|---|---|
| **kWh** | Unit of electricity used; the bill charges per kWh. |
| **kWp** | Kilowatt-peak: the size of a solar system. In Ilocos Norte, 1 kWp makes roughly 3.5–4.5 kWh per day. |
| **Clearness index (kt)** | Fraction of the sun's energy that reaches the ground (0 = very cloudy, ~0.75 = clear sky). |
| **Markov chain** | A random model where the next state depends only on the current one (tomorrow's weather depends on today's). |
| **TPM** | Transition probability matrix: the table of "if today is X, the chance tomorrow is Y". |
| **Monte Carlo** | Repeating a random simulation many times to see the full range of outcomes. |
| **Common random numbers (CRN)** | Using the same random weather for every PV size so the comparison is fair. |
| **Net metering (RA 9513)** | Exported solar kWh earn a credit on the bill. The `--offset` option sets whether the credit is worth the full bill rate (`bill`) or only the generation charge (`generation`, more realistic). |
| **Unbundled rate** | The bill split into separate charges (generation, transmission, distribution, VAT, ...). |
| **P10 / P90** | 10% of simulated years have a bill below P10, and 10% above P90. |
| **CVaR95** | Average bill in the worst 5% of cases: a measure of bad-year risk. |
| **Payback** | Years until the bill savings repay the cost of the panels. |
| **Sobol index** | Share of the uncertainty in the answer caused by each input. |
| **Calibration** | Scaling the model so it reproduces the real bill (464 kWh, ₱5,739.45). |
